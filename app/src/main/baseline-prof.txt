# Curio — starter baseline profile (v332).
#
# Manually-authored HRF rules. AGP bundles this file into
# assets/dexopt/baseline.prof, and ProfileInstaller (declared explicitly in
# app/build.gradle.kts, already present transitively via Compose) installs it
# on first launch so ART AOT-compiles these methods at install time instead
# of JIT-compiling them at runtime.
#
# Why: the 2026-09-03 logcat showed the JIT compiling giant single methods
# (e.g. the 30-arg share-card / category-picker composables) at up to
# 7.7 MB of compiled code each, plus a ~6 MB "Compiler allocated" spike per
# method — a real memory/CPU cost on first runs, worse on low-RAM devices.
# These rules AOT-compile the same code paths once, at install.
#
# HRF syntax notes (validated against the profgen docs and a CI failure):
#   * Flags H / S / P (Hot / Startup / Post-Startup) are ONLY valid on METHOD
#     rules. "L" is the DEX descriptor prefix, not a flag.
#       HSPLcom/curio/app/MainActivity;->**(**)**
#   * CLASS rules take NO flags (they only pre-allocate the class in the
#     heap):  Lcom/curio/app/MainActivity;
#   * Package-wide AOT uses the wildcard method rule:  <pkg>/**->**(**)**
#
# Release builds run R8 (minify ON): AGP rewrites these source-symbol rules
# through the R8 mapping automatically, so source names are correct here.
#
# Keep in sync with the app's actual hot paths; extend with a
# Macrobenchmark-generated profile if one is ever added.
